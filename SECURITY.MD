# Explanation of `securityHeaders` Configuration

This document explains the structure and purpose of each item in the `securityHeaders` array from a typical security configuration in a Next.js project.

```js
const securityHeaders = [
  ...createSecureHeaders({
    frameGuard: "sameorigin",
    xssProtection: "block-rendering",
    noopen: "noopen",
    nosniff: "nosniff",
    forceHTTPSRedirect:
      process.env.NODE_ENV === "production"
        ? [true, { maxAge: 60 * 60 * 24 * 360, includeSubDomains: true }]
        : false,
    referrerPolicy: "same-origin",
  }),
  {
    key: "X-Permitted-Cross-Domain-Policies",
    value: "master-only",
  },
];
```

## Headers Generated by `createSecureHeaders`

### 1. `frameGuard: "sameorigin"`

- **Header Added**: `X-Frame-Options: SAMEORIGIN`
- **Purpose**: Prevents clickjacking by disallowing your site from being embedded in iframes on other domains.

### 2. `xssProtection: "block-rendering"`

- **Header Added**: `X-XSS-Protection: 1; mode=block`
- **Purpose**: In older browsers like Internet Explorer, blocks rendering the page if XSS is detected.

### 3. `noopen: "noopen"`

- **Header Added**: `X-Download-Options: noopen`
- **Purpose**: Prevents Internet Explorer from opening downloaded files automatically, mitigating potential security risks.

### 4. `nosniff: "nosniff"`

- **Header Added**: `X-Content-Type-Options: nosniff`
- **Purpose**: Prevents MIME-type sniffing, which can lead to security vulnerabilities when the browser incorrectly interprets the file type.

### 5. `forceHTTPSRedirect`

- **Header Added** (if in production):  
  `Strict-Transport-Security: max-age=31104000; includeSubDomains`
- **Purpose**: Forces the browser to use HTTPS for all connections for 1 year, including subdomains.

### 6. `referrerPolicy: "same-origin"`

- **Header Added**: `Referrer-Policy: same-origin`
- **Purpose**: Limits referrer data to same-origin requests only, preventing information leakage to third-party websites.

## Additional Custom Header

```js
{
  key: "X-Permitted-Cross-Domain-Policies",
  value: "master-only",
}
```

- **Purpose**: Restricts Adobe Flash and PDF cross-domain access. `master-only` means only the root policy file (`/crossdomain.xml`) is respected, enhancing legacy security.

## Summary

These security headers work together to improve your web app’s protection against:

- Clickjacking (`frameGuard`)
- XSS attacks in legacy browsers (`xssProtection`)
- MIME-type sniffing (`nosniff`)
- Insecure downloads (`noopen`)
- Unencrypted HTTP access (`forceHTTPSRedirect`)
- Referrer data leaks (`referrerPolicy`)
- Legacy plugin vulnerabilities (`X-Permitted-Cross-Domain-Policies`)

They represent modern best practices and are highly recommended for any secure web application deployment.
